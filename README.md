# Apex

> 端，体之无序而最前者也。 —— 《墨经》
>
> **Apex. The first point.**

*[English](README.en.md)*

**端** —— 物体分割到不能再分时，最靠前的那个点。最小的单位，也是最初的起点。

---

## 这是什么

一个 Windows 工具集（类似 PowerToys 的形态）：**每个功能只做一件事，做到最好**。

现在有四个功能：

| 功能 | 做什么 |
|---|---|
| **丝滑滚动**<br>Silky Scroll | 全局接管鼠标滚轮——任何程序里滚动都带加速和收尾，变成平滑运动 |
| **自动输入法**<br>Auto IME | 按当前焦点所在的程序或控件，自动切换中英文输入法；规则可以拖动排序、点一下再按键来录制 |
| **保持唤醒**<br>Keep Awake | 一张程序列表，每行两个开关——「保持唤醒」和「阻止熄屏」；另有一行不可删的「系统全局」 |
| **媒体控制**<br>Media Control | 每台显示器一个亮度推子、一个熄屏按钮；每个应用一个音量推子和一个静音按钮 |

每个功能**各管各的**：各有自己的开关、自己的设置文件、自己的「排除」名单，互不相干。

## 与两个自带引擎的项目

**丝滑滚动**是**全局**接管：它在整个系统里把滚轮消息变成平滑运动。但有些程序**自己就带平滑引擎**，
在那里再叠一层只会打架——所以 Apex 让路：

| 项目 | 是什么 | Apex 怎么处理 |
|---|---|---|
| **[SmoothWheelScroll](https://github.com/bobo198504/SmoothWheelScroll)** | REAPER 的平滑滚动插件，也是本项目平滑模型的来源（`shared/` 里就是它 `src/` 的副本） | REAPER 的滚轮一概不接管，**不管插件有没有加载** |
| **[Lertaro](https://github.com/Lertaro/Lertaro)** | 独立的 Windows 工具，移植了同一套平滑模型，启用平滑时会发布一个命名事件 | Lertaro 的滚轮一概不接管，**不管它的平滑有没有打开** |

判断依据是**程序本身**，不是"它的引擎此刻开没开"——否则你一打开插件，手感就会在两种平滑之间来回切换。

设置页里，**丝滑滚动**的「排除」右边有一行灰字，列出此刻真的在跑的引擎
（`REAPER、Lertaro专用引擎已运行`，谁先启动谁在前）。那行字只是**告诉你**；让路这件事与它无关，永远生效。

以后再有程序自带平滑引擎，加进来只改一处（`common/engines.h` 的一张表），提示和让路会同时生效。

## 用法

1. 运行 `apex.exe`，托盘出现图标
2. **单击**托盘图标 → 弹出**快速面板**（浮在托盘图标上方的小面板）
3. **双击**托盘图标，或右键 → **设置**，打开设置面板
4. 滚轮在任何程序上都会平滑滚动
5. 想让某个程序不受**某个功能**影响，在那个**功能页的「排除」**里加上它的名字
   （如 `game.exe`，支持 `*` 和 `?`）

关闭某个功能：在面板里点左侧那个功能，把它自己的开关关掉即可。
Apex 没有全局总开关——**每个功能管自己的启用**。

> ⚠️ **刚装上时所有功能都是关闭的**，需要哪个就打开哪个。已有的设置文件不受影响。

## 快速面板

托盘**单击**浮现的那个小面板。它不是设置面板，而是宿主进程里的一个自绘窗口，
出现在托盘图标上方——因为「点一下托盘」期待的是立刻有东西，而设置面板是一个浏览器进程，
冷启动要半秒以上。

- 每个功能在这里放自己的控件：开关、推子、按钮
- 具体放哪些，由**功能自己**声明；有的默认不进这块面板，要在功能页里打开
- 名字太长放不下的，鼠标停上去会来回滚动显示

## 便携

整个文件夹拷走即可，设置跟着走。不写注册表、不写 `%APPDATA%`。

```
apex.exe              主程序
apex.ini              主设置
apex-settings.exe     设置面板
Plugins\<功能名>\      各功能，含它自己的设置
```

一个例外：**「开机启动」**（默认关闭）会写一个启动项到系统里——那是全程序唯一写在自身文件夹
之外的东西，所以它默认是关的。

首次打开设置面板后会多出一个 `WebView2\` 文件夹，那是设置面板用的浏览器自己建的缓存目录，
属于本机产物，不用管它，也不要拷给别人。

## 设置

中英双语，跟随系统明暗，**参数改动实时生效**（不用重启）。

左侧最上方就是**通用设置**（端 / Apex 那块，点它进入），下面是各功能的列表。

- **通用**：语言（跟随系统 / 中文 / English）、外观（跟随系统 / 浅色 / 深色）、开机启动，
  以及快速面板那两半各开关不开关
- **功能页**：每个功能自己的一页。开关只有一个（就是它自己的启用）；
  滑块**双击恢复默认值**，也可以把鼠标停在上面用滚轮改值
- **「排除」列表**：在功能页里，列进去的程序对该功能原样放行。
  ⚠️ **它是这个功能自己的**——别的功能有没有这张列表、叫什么名字，由那个功能决定

改了什么、每一版加了什么，见 **[CHANGELOG.md](CHANGELOG.md)**。

## 构建

```bash
bash apex/build.sh                # 构建，产物在 build/apex/
bash test/run_all.sh              # 构建层：纯逻辑与产物，不起进程、不碰输入设备（随时可跑）
bash test/run_all.sh --assembly   # 再加上装配层：会起真程序，交付前跑一次
bash apex/package.sh              # 打成便携包 build/Apex-<版本>-portable.zip
bash apex/deploy.sh               # 部署到本机的安装目录
```

需要 **MinGW-w64**（`g++` / `windres`）。项目用 [w64devkit](https://github.com/skeeto/w64devkit)
开发，脚本顶部有一行默认的工具链路径，改掉它、或者把你的工具链放进 `PATH` 都行。
不需要 REAPER SDK、不需要 CMake；WebView2 SDK 已随项目附带（`third_party/`）。

`apex/package.sh` 只把程序文件打进包里（exe/dll），打完还会读回来自检一遍——
`build/apex/` 同时是作者跑过程序的目录，随手打包会把自己的设置和日志一起打进去。

## 开发

结构与约定见 **[AGENTS.md](AGENTS.md)**（每天必读的核心；按主题的分册在 `docs/rules/`）。要点：

- **功能 = 一个文件夹**（`features\<id>\`），实现 `apex/abi.h` 的 C 接口
- **界面不用为每个功能写**：功能描述自己的控件，面板照着画
- **设置与钩子是两个进程**：面板卡死不影响滚动
- **模型在 `shared/`**，是 SmoothWheelScroll 插件项目 `src/` 的副本，两边要手动同步
  （`test/check_model_sync.sh` 会比对）
