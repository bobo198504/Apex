# Mica on the panel: can it be done, is it worth it, what does it cost（实测记录，2026-09-21/22）

> 起因：用户问「UI 可以 mica 材质吗？」，看过两张图后说「效果不是很明显，所以我要重新考虑值不值得做，
> 而且这个会有多少额外的性能开销？」
> 这是**回答问题用的实测**，不是设计文档。
> 工具：`_diag/mica_probe.cpp` + `_diag/mica_probe.sh`（画面）与 `_diag/mica_gpu.ps1`（GPU 开销）。
> **所有数字都来自屏幕取样**（`GetPixel` 读 DWM 合成之后的画面），不是「我看上去像」。

## ★ 决定（2026-09-22）：**不做**，结论收进本记录

**口径（用户原话）**：「现在主UI不做，保持原样，以后有其它另外出现的UI再另说。」
→ **主界面（`apex/ui/` 那套面板）一行不改**；将来若出现**别的 UI**（新的窗口/界面/功能页），再单独议——
那时**本记录可以直接复用**：第一节的坑、第二节的可见度、第三节的开销、第四节的配方与代价清单，都是现成的。

理由一句话：**能做成，但 Mica 的效果按设计就是极淡**（活动态 4 种颜色，退化态 1 种），而"看得见"的那两个
（Acrylic / Mica Alt）一个 GPU 开销明显更高、一个染色太重。**代码一行没改**——本次只新增了 `_diag/` 下的
探针与记录，产品源码、门、产物都没动（构建层 16 扇门全绿）。

## 一、⚠️ 先说一个我自己造成的错误：那两张图不是 Mica

官方 [Mica 文档](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)原文：Mica 会在这些情况下变成
**一块纯色**（`SolidBackgroundFillColorBase`）——用户关掉透明效果、**省电模式**、低端硬件、
**桌面窗口失去激活**、系统低于 22000。

我第一次跑完整套时的日志里写着 `capture: ... foreground=0`：**窗口当时不是活动窗口**，量到的 `#F3F3F3`（浅）/
`#202020`（深）正是那两个纯色值。**用户看到并否掉的那两张图，是退化态。**

修法不是解释，是**把"窗口必须是活动窗口"变成一条硬检查**（`mica_probe.sh` 里 `foreground=1`，不满足就 FAIL），
并且探针现在会用 `AttachThreadInput` 主动把窗口变成活动窗口（不注入任何鼠标键盘输入）。

## 二、修正之后的画面：材质出来了，而且**确实很淡**

活动态（`foreground=1`、色键开、采样带是页面留透明的那块客户区）：

| 材质 | dark | 平均色 | 亮度 | **颜色种数** | 说明 |
|---|---|---|---|---|---|
| **Mica** | 1（深） | `#261E1A` | 31.3 | **4** | 暖色偏染的近黑（R 38 > B 26 = 壁纸的暖调进来了） |
| **Mica Alt** | 1 | `#130600` | 9.5 | **5** | 染色更强、更暗（官方：「stronger tinting」） |
| **Acrylic** | 1 | `#414042` | 64.7 | **37** | **看得出纹理**，min 61 max 104 |
| **Mica** | 0（浅） | `#F9F1EC` | 242.0 | 3 | 暖白，带壁纸色调 |
| Mica（**退化态**） | 0 | `#F3F3F3` | 243.0 | **1** | 不活动时的纯色——就是用户看到并否掉的那张 |
| 无材质（洞） | 1 | `175,132,111`（另一次 `31,31,33`） | 142.5（另一次 31.3） | **221**（另一次 **6**） | ⚠️ **取决于窗口背后恰好是什么**，见下 |

⚠️ **"无材质 = 洞"这个对照物不可靠，不能当判据。** 同一句 `--backdrop=none` 量到过两次完全不同的结果：
背后是壁纸时 **221 种颜色**（桌面的细节），背后是一扇深色窗口时 **`31,31,33`、6 种颜色**——与深色 Mica 的
`38,30,26` 只差 **8**。也就是说这个对照"失败"的时候，材质其实画得好好的（**是环境变了，不是产品变了**）。
所以脚本的**判据**改成两条不依赖桌面的：

- **b. 色键真的挖出了洞**：有键 vs 无键（同为 mica）距离 **665** → 有键时不再是窗口自己那块不透明的白面；
- **c. 洞里是材质、不是桌面**：**只翻这个窗口的 dark 标志**，距离 **632** —— 桌面不会因为这个标志而变化，
  材质会。**这是材质的指纹，也是这个环境里唯一无法由"桌面透出来"满足的判据。**

至于"可见度"（下面 e 那组数）才是决定值不值得做的那一项。

**读法**：`颜色种数` 是"这块材质到底有没有内容"的判据。纯色 = 1；Mica 是 3~5（**只有一点色调**）；
Acrylic 是 37（**有真实的纹理**）。

**所以用户"效果不明显"的判断是对的，而且不是测量问题**：Mica 的设计就是**极淡**——它是"不透明的、带上一点
主题与壁纸色调的底"（官方定义），不是毛玻璃。**要看得见的效果，正确的候选是 Acrylic（有纹理，代价更高）
或 Mica Alt（染色更强，代价与 Mica 同一量级）。**

## 三、性能开销（先给结论，再给数字）

**结论：Mica 的稳态开销落在噪声里；Acrylic 明显高出一截。而这两笔账都是 DWM 付的，不是 Apex 付的。**

### 3.1 官方说法（不是我的推断）

- **Mica**：「specifically designed for app performance as it **only samples the desktop wallpaper once**」。
- **Acrylic**：「Rendering acrylic surfaces is **GPU-intensive**, which can increase device power consumption and
  **shorten battery life**」；且省电模式/关闭透明效果时自动退化成纯色。

### 3.2 实测（`_diag/mica_gpu.ps1`，dwm.exe 的 GPU 计数器求和）

| 模式 | dwm GPU 均值 | 相对空载基线 |
|---|---|---|
| 空载（没有任何探针窗口） | 2.01 | —— |
| **plain**（不透明窗口、无材质）——今天的面板大致就是这样 | 1.26 | **−0.75** |
| **hole**（分层+色键、无材质） | 2.34 | +0.33 |
| **mica** | 2.50 | +0.49 |
| **micaalt** | （见脚本，与 mica 同量级：静态材质） | —— |
| **acrylic** | 3.89 | **+1.88** |

⚠️ **这张表要按"同一量级"读，不能按小数读**：采样约 1.4 s 一次、空载基线只测了一次、桌面当时是活的。
**噪声底线就写在表里**：`plain`（不透明、什么都没变）竟然比空载还低 0.75。也就是说 **±1 以内等于没测到**——
因此 **mica 的 +0.49 落在噪声里，acrylic 的 +1.88 明显超出**。

### 3.3 CPU 那一侧

- **Apex 自己（探针进程）**：8 秒驻留期间 CPU 增量**低于 Windows 的 15.6 ms 计时粒度**（报 `0ms`；早先 2.6 秒
  那次报 `47ms`）——即**可以忽略**，且这不是材质画在哪儿的问题：材质不是 Apex 画的。
- **dwm.exe 的 CPU 时间读不到**（`(Get-Process dwm).TotalProcessorTime` 为空、探针 `OpenProcess` 也被拒），
  **所以这里没有 dwm CPU 数字，不编**。DWM 那一侧用的是上面的 GPU 计数器。

### 3.4 现有代价（与材质无关，别混为一谈）

面板打开时 WebView2 的 6 个浏览器进程约 **152 MB**，关掉即释放、宿主始终约 2.5 MB（见 `_diag/UI_DECISION.md`）。
**Mica 不改变这部分**；它多出来的是 DWM 侧的一张静态材质面。**没量的一条**：透明 WebView2（A=0）那层
alpha 面本身的内存——真要做得量。

## 四、如果真要做，面板要付的代价（**未实施，仅供决策**）

| 层 | 现在 | Mica 版 |
|---|---|---|
| 窗口 | 普通窗口，`WM_ERASEBKGND` 填 `PageBgColor` | **分层 + 黑色键**，客户区填键色 |
| 边框 | `DWMWA_BORDER_COLOR` = 页面底色 | 那是一笔**不透明的线**，会压在材质上 → `DWMWA_COLOR_NONE` |
| WebView2 | `DefaultBackgroundColor` = 页面底色（不透明） | **A=0**（官方：alpha **只接受 0 和 255**） |
| 页面 | `body`/`#side` 用 `--bg` | 外层透明，**卡片 `--panel` 保持不透明** |
| 门 | `check_apex_flash.sh` 比「面板告诉浏览器的颜色 == 页面 `--bg`」 | 这条比较**失去意义**，要换一种写法 |
| 门 | `check_apex_palette.sh` 的 `fg on bg` / `sub on bg` | 背景不再确定；**卡片不透明**则卡片上的那几条仍成立 |
| 回退 | —— | **Win10 / 关掉透明效果 / 省电模式 / 窗口不活动 → 一律变成纯色**，所以现在这套纯色必须留着 |

**另有一笔没量的账**：`WS_EX_LAYERED` 对**截图类**行为的影响（`_diag/apex_panel_shot.cpp` 用的 `PrintWindow`
以及几扇面板门依赖它）。真要做时先量这一条。

## 五、⚠️ 环境限制：探针不能在受限沙箱里跑

受限沙箱里 **WebView2 的浏览器进程会崩**（`msedgewebview2.exe`，`0x80000003`，屏幕上弹「应用程序错误」框），
而且 **Git Bash 起不来**（`couldn't create signal pipe, Win32 error 5`）。**不是探针的 bug**：产品自己的
`apex-settings.exe` 在同一个沙箱里也一样（`WebView2 controller failed (0x8000ffff)`）——受限模式挡住的是
WebView2 赖以通信的命名管道。**在普通 shell 里跑就正常。**

## 六、仪器自检（不然上面所有数字都不算数）

- **窗口外取点**：`(5,5)=#614230`、左 `#AF836C` —— 画面是真的桌面。
- **GDI 对照块**：自己画 `#FF00FF`，从截图读回 `#FF00FF` —— 截图看的确实是这个窗口。
- **页面卡片对照点**：`#2F7FD4` 原色读回 —— 页面确实画在这张图上（即"页面压在材质上"成立）。
- **`foreground=1` 硬检查** —— 见第一节：没有它，一切都可能是在量退化态。
- **`dwm.exe handle`**：读不到就**明说读不到**，而不是报一个 0 冒充测量值。
