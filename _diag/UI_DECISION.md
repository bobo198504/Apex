# Apex 界面方案：实测数据与结论（2026-09-18）

> 起因：用户问"现在的 UI 是不是最好的方案？有没有兼容性更好、更容易维护的？"
> 这是**回答问题用的实测**，不是设计文档。结论在最后一节。

## 一、实测开销量（本机，Win11 10.0.28000，WebView2 Runtime 153）

| 状态 | Apex 家族私有内存 | 浏览器进程 |
|---|---|---|
| 只有宿主 `apex.exe` | **2.5 MB** | **0 个** |
| 面板打开 | 9.7 MB（两个 exe）+ **152.3 MB**（6 个浏览器进程） | 6 |
| 面板关闭后 | **2.4 MB** | **0 个** |

**结论：面板关闭时不占任何浏览器资源，打开的代价约 152 MB，关闭即释放。**

### ⚠️ 一个差点误判的地方（记住）

我曾看到系统里有 **18 个 `msedgewebview2.exe`、共 491 MB**，第一反应是"这就是我的面板"。
**不是。** 用命令行里的 `--user-data-dir` 归类后：

| 数量 | 归属 |
|---|---|
| 5 个 | **Waves Audio 的插件界面**（REAPER 里开着的 Waves） |
| 5 个 | **Windows 系统组件**（`MicrosoftWindows.Client.CBS`） |
| 2 个 | 无 user-data-dir |
| **0 个** | **Apex** |

**教训：`msedgewebview2.exe` 是共享基础设施，任何人装了 WebView2 应用都会看到它们。
判断"是不是我的"，必须按 `--user-data-dir` 归类，不能按进程名数。**

## 二、技术方案对比（针对 Apex 的实际需求）

需求（用户提出）：**中英双语 + 明暗跟随系统 + 多平台 + 好维护 + 好看**。

| 方案 | 首次投入 | 加新功能 | 加新平台 | 明暗跟随 | 占用 | 风险 |
|---|---|---|---|---|---|---|
| **WebView2（现状）** | 已完成 | **零 UI 代码**（功能自带 JSON 描述） | 换 webview 即可，页面不动 | **CSS 原生** | 开面板 152 MB | 依赖 WebView2 Runtime（Win10/11 基本都有） |
| Qt | 大 | 中等 | 好 | 需自己写 | 大（几十 MB） | GPL/商用授权 |
| Dear ImGui | 中 | 小 | 好 | 需自己写 | 小 | 观感偏"工具"，不适合成品桌面应用 |
| 原生 Win32（像 REAPER 插件那样） | 已完成过一次 | 每个功能都要写一遍 | **每个平台重写** | 自己实现（插件里已知有坑，§19.1/19.21） | 极小 | 中英双语要自己排版 |
| Tauri / Electron | 大 | 零 | 好 | CSS | 更大 | 多一个运行时；Tauri 要 Rust |

## 三、结论

**维持 WebView2 方案。** 理由按重要性排序：

1. **加功能不用碰 UI 代码。** 功能用 `settingsJson()` 描述自己的控件（滑块/开关/曲线），
   面板照着画。这是"把 SmoothWheel 做成功能集里的一个"这个结构成立的前提——
   如果每个功能都要写一遍面板，PowerToys 那种形态维护不下去。
2. **明暗换肤是 CSS 的事，不用自己写。** 插件那边为暗色标题栏和滚动条栽过两次
   （§19.1 的递归、§19.21 的崩溃），Web UI 天然没有这类问题。
3. **占用只在打开时存在**，实测关闭即释放（152 MB → 0）。
4. **跨平台铺好了路**：页面不变，换 webview 后端（macOS 用 WKWebView、Linux 用 WebKitGTK）。

### 已知代价（要如实说）

- **152 MB 是打开面板时的开销**，对一个设置窗口来说不算小。可接受的理由：它是**浏览器进程**，
  关掉就释放，且不影响宿主（宿主始终 2.4 MB）。
- **依赖 WebView2 Runtime**。缺失时面板会弹提示并引导安装（代码里已处理），
  **宿主不受影响**（宿主不依赖它，只有面板 exe 依赖）。
- Linux 上没有 WebView2，要换 WebKitGTK；这是将来的事，页面不用改。

## 四、如果将来要换，换什么

**不要换 Electron/Tauri**（多一个运行时，占用更大）。
若某天嫌 152 MB 大，正确方向是**面板只在需要时创建浏览器**（现在就是），
而不是换框架——框架换掉，上面第 1、2 条好处全没了。
