# 设置面板：协议与页面踩过的坑（AGENTS 分册）

> **何时读我**：要改 apex/ui/panel.html、ui_webview.cpp、settings_host.cpp，或者页面上的任何一种控件。
>
> 本册是从根目录 AGENTS.md 拆出来的正文，**内容与拆之前逐字相同**（只是搬了家）。根目录那份末尾有索引；
> 判据与理由都在正文里 —— 不要在这里写摘要，摘要会漂移，正文不会。

### 3.4 设置面板是**独立进程**，协议是 WM_COPYDATA

- **为什么分**：钩子在 OS 输入路径里。渲染浏览器、等用户操作、可能被任务管理器杀掉的窗口，
  不能影响它。分开之后面板可以卡死/被杀/重启而平滑照跑。
- **协议**（`apex\settings_ipc.h`）：小请求 + 文档应答，两个方向都是 `WM_COPYDATA`。
- ⚠️ **指针不能跨进程**。第一版把调用方的缓冲区地址放进请求里让宿主填——那是错的，
  宿主会写进自己的地址空间。应答也走 `WM_COPYDATA`（见协议头的说明）。
- ⚠️ **`WM_COPYDATA` 的发送方在 `WPARAM`**。第一版传了自己的窗口句柄，于是宿主回复给了自己，
  面板永远等不到应答，表现是"面板说宿主没在运行"。
- ⚠️ **应答只在面板的 `WndProc` 里收，`IpcClient` 不存副本。** 它曾经存过（`OnCopyData`/`Answer`），
  而**没有任何人读**——因为只有 `WndProc` 知道这份文档是快照还是控件。留着那份副本会让读代码的人
  以为应答从 `Send()` 出来。现在是：`Send()` 只管发、返回宿主的状态码，`WndProc` 只管收。
- ⚠️ **宿主会死，面板必须自己发现。** 判据是**面板进程**轮询 `FindWindow(APEX_HOST_WND_CLASS)`
  （`ui_webview.cpp` 的 `SetTimer`，2 秒），变化时调页面的 `__apexHostGone` / `__apexHostBack`。
  **页面自己查不了**（浏览器页面看不到别的进程的窗口）——它原来那段 `setInterval` 两个分支都 return，
  是个空循环，注释还写着"好让提示出现"。**一个看起来合理、位置也对、却什么都不做的轮询，
  比没有更糟**（它让人以为这件事已经处理了）。

### 3.5 面板页面已踩过的坑（**别再犯**）

0. **⚠️⚠️ 组里的字段曾经只按"文本框"画，不管它是什么类型**（2026-09-23，用户报的）。`groupField` 的注释写着
   "everything else in a group is TEXT -- the patterns are the whole point of this feature"——那是**关于一个功能的
   观察**（AutoIME 的规则：进程名、窗口标题），却被当成了**契约**，而 ABI 说组里的字段可以是**任何**控件类型。
   后果是 MediaControl 那一页：`range` 画成了数字输入框、`hotkey` 画成了普通文本框——用户的原话是
   「**亮度和音量在设置面板里的调整，也要用推子**」和「**熄屏快捷键不能录入和生效**」。
   **两边的文档都是对的，页面把五种控件画成了第六种。**
   - **修法不是再写两个控件**，而是让 `rangeRow` / `hotkeyRow` 多收一个 **path 参数**（组里的地址是
     `offkeys[1].hotkey`，不是 `hotkey`），然后在 `groupField` 里分派到**同一批函数**。
     **判据：同一个控件在两种布局里必须是同一个实现**——两份会漂移，而漂移的表现是"某一处能拖、另一处不能"。
   - ⚠️ **它的门原来也看不见**：`check_apex_panel.sh` 用 DOM 桩测的是"控件画出来了没有"，而一个数字输入框
     和一个推子都是"画出来了"。**一个把类型画错的页面，在按类型断言的桩面前是隐形的**——除非桩也断言类型。

1. **控件在构建时不能发消息。** 填充 `<select>` 会触发 `change` → 处理器发 `setHost` →
   宿主回快照 → 重新渲染 → 再触发。**实测**：没人碰，设置自己在 `zh→auto→en→dark→light` 来回走。
   修法是**比较**：值等于宿主刚上报的值就不是编辑，不发。`selectRow`/`switchRow` 里各有一处。
2. **`#body` 里的东西会被重绘删掉。** 两个渲染函数都 `innerHTML = ""` 清空 `#body`，
   而"宿主未运行"的提示条原本在里面 → 第一次渲染就把它删了 → 之后每次点击抛异常、页面半死。
   现在提示条是 `#body` 的**兄弟节点**（`#banner`）。
3. **“改状态”不等于“改显示”。** 设了 `S.connected = true` 却没调 `renderConn()` 隐藏提示条，
   于是宿主明明在运行，面板却挂着红字警告。**截图发现的**。
4. **⚠️「设了文字和样式」也不等于「接上了事件」。** 通用入口（`#brand`）以前是个底部按钮：
   `renderNav` 每次渲染都给它 `textContent` 和 `className`，**却从来没有 `addEventListener`**——
   代码看上去完全正常，表现是"进了插件页就回不去通用页"。
   - **事件的绑定写在 boot 处，一次；不要写在每次都会重跑的渲染函数里**——那样每渲染一次就多叠一个监听器。
   - **探针的 DOM 桩原来是 `addEventListener() {}`（收到就丢）**，所以它**分不出"接好了"和"根本没接"**。
     桩现在**保存监听器**并提供 `fire()`，`apex_panel_probe.js` 里有断言真的去点它。
5. **⚠️「点了没反应」也可能是 CSS 把点击吃掉了。** 开关的 `.tr`/`.kn` 是**绝对定位的装饰 div，排在
   `input` 之后**——它们盖在 checkbox 上，**命中测试跟着绘制走**，所以点击落在 div 上。
   checkbox 永远不切换、`change` 永远不触发，而**处理函数本身完全正确**。
   修法是 `.sw .tr, .sw .kn { pointer-events: none; }`。
   **⭐ 这类 bug 页面级探针永远查不到**（DOM 桩没有布局、没有命中测试），**只能靠真实点击**：
   `_diag/apex_click.c` 点一下，再看宿主/面板日志里那条消息有没有出现。
   "开关不能用"就是它。
6. **⚠️「页面不全」可能不是渲染少画了，而是根本没去要数据。** 控件**不在快照里**：页面必须发
   `describe` 才拿得到（`loadFeature` 里那一行）。点列表行的处理器原来写的是
   `S.view = f.slot; renderAll()`——**从来没发过 `describe`**，于是功能页画出来是"开关 + 一张空卡片"。
   表现是"设置页面不全"，实际是**请求缺失**。
   - **判据：页面上的每一块内容，都要能指出它是从哪条消息来的。** 指不出来，它就是空的那块。
7. **⚠️ 拖动滑块时不能重建页面。** 宿主原来对**每个命令**都回一次快照（"答即刷新"），
   而 `setFeature` 是**按像素**发的——快照让页面重新请求控件、重建自己，**把用户正按着的滑块删掉**。
   实测：滑块能点、**不能拖**。修法是两条：宿主对 `setFeature` **不回快照**（页面已经知道自己刚发的值，
   而快照里的宿主设置和功能列表不会因为拖滑块改变）；页面**在 `change`（拖动结束）才请求曲线重画**，
   不在 `input` 里做。**热路径上的"顺手刷新"就是这个下场。**
8. **⚠️「协议变了，读的地方没跟着改」＝ 整块功能静默消失。** 曲线卡片那次：数据契约从
   `curve:{shape,native,paceMs}`（移植来的图表）简化成 `curve:[{x,y}...]`（点数组）时，
   `drawCurve` 和调用点都改了，**唯独外面那个准入条件还在问 `.shape`**。数组没有 `.shape` →
   条件恒假 → **卡片根本不生成**；而"渲染函数里一个条件不成立"和"功能没发曲线"从外面看**一模一样**。
   - **判据**：改一个数据格式，要搜**所有**读它的地方（包括 `if` 的守卫、注释里的示例）。
   - 更早的那次同款：`apex_panel_probe.js` 喂的还是旧格式，所以探针一路绿灯。**探针喂的数据必须和功能真发的一致。**
9. **⚠️ 回声守卫不能拿「建卡时的参数」当基准。** `switchRow`/`selectRow` 里写的是
   `if (inp.checked === !!checked) return;`，而 `checked` 是**实参**，建完就冻住了：
   点一下之后控件与它相反，**第二次点击正好等于那个旧值，被当成回声丢掉**——不发消息、不重绘，
   表现是"开关只能用一次"。功能自己的 `bool` 参数最惨，因为 `setFeature` **故意不回快照**，
   没有任何东西会来纠正界面。**守卫要比的是"我们最后告诉宿主的那个值"（一个会变的变量），不是入参。**
10. **⚠️ 用户输入进 JSON 必须转义。** 功能手拼 `describe` 文档，黑名单条目直接 `"%s"` 塞进去；
   而 `NormaliseExe` 不拒绝引号——输入一个 `a"b` 就能造出非法 JSON，页面 `JSON.parse` 抛错、
   功能页变陈旧。宿主的 `Json::Str` 只保护**它自己**拼的快照，**转发的那份它看不见**。
   修法：`AppendJsonString()`，**所有**字符串走它，包括"看着安全"的。
11. **⚠️ 滚轮改值要按 `step` 走，而且要累加。** 滑块支持滚轮（`rangeRow` 的 `wheel` 处理器）时有两处
   不这么写就会坏：**①按控制自己的 `step` 走**，不能按像素或固定单位——`step` 是功能声明的粒度，
   自己另定一个就等于绕过它；**②按 120 累加**，不能"一个事件一步"——触控板一次只报几个 delta，
   一步一格的话要划四十下才动一档，而**带刻度的鼠标一次正好 120**，所以累加器让两者**速率一致**。
   数值要**贴回网格**（`(v-lo)/step` 取整再乘回去），否则 0.1 这种步长在浮点里累积漂移，
   浏览器会在下次渲染时按自己的意思取整——**显示的数就不再是发出去的数**。
   - **前提是宿主放行我们面板上的滚轮**（§3.6.3）；那两个是同一件事的两半，注释在两边都写了。
   - ⚠️ **`apex_panel_probe.js` 的 DOM 桩必须给事件对象带 `preventDefault`。** 页面调它（滚轮不许
     同时滚页面），真实浏览器永远有，**桩没有就成了"能用的页面看着像坏的"**——和缺 canvas 方法同一类坑。

12. **⚠️「窗口显示了」不等于「里面有东西」。** 用户报「设置刚打开时，会有一小段时间面板是空的」——
    **窗口在 `CreateWindowEx` 之后立刻 `ShowWindow`，而那时 WebView2 还没被创建**（`ui_webview.cpp`：
    `ShowWindow` 在 `CreateCoreWebView2EnvironmentWithOptions` **之前**）。浏览器起来 + 页面跑完 + 第一次绘制
    要好几百毫秒，这段时间窗口里就是一块**背景色**。**修法不是画得更早，是显示得更晚**：窗口建好后保持隐藏，
    页面画完第一帧再 `postMessage({cmd:"ready"})`（用**两次 `requestAnimationFrame`**——一次只代表"即将绘制"），
    由 `ShowPanelOnce` 显示；再加一个 **900ms 兜底计时器**（WebView2 起不来时窗口必须仍能出现，否则
    "没显示"和"没启动"从外面看一模一样）。
    **实测**（装配层门的真进程日志）：`page -> host: ready` → `panel window shown (the page is drawn)`。
    同一处的第二条：**"还没答复"不等于"宿主没在运行"**——`S.connected` 因此是三态（`null`/false/true），
    否则每次启动都先红字骂一句宿主（`renderConn`）。
13. **⚠️ 热路径上的"顺手刷新"要先问它会不会重建正在被操作的东西，再问能不能只重建其中一块。**
    曲线实时化那次（用户报「原先可以随上面四个参数值实时变化，现在只是改完值后才动一下」）：曲线是**功能算出来的**，
    拖动中要跟着变就只能再问一次；可 `describe` 的答复会**重建整页**，把用户正按着的滑块删掉（§3.5.7 那个坑），
    于是当初退到 `change`（拖动结束）才刷新——**实时性就是这么丢的**。
    现在的做法：**问题本身带上用途**（`pendingDescribes` 里是 `{slot, curveOnly}`）——`curveOnly` 的答复**只重画 canvas**
    （`redrawCurveInPlace`，且**不动 `curveBorn`**，否则飞在半路的球会被删掉），页面别处一根手指都不碰；
    节流 **80ms**，**不是防抖**（防抖要等用户停手，正是"只动一下"的成因）。拖动结束的 `change` 仍整页重读一次，
    让功能**钳位/取整**后的值回到界面上。

14. **⚠️⚠️ 布局问题不许猜，也不许用桩验——用真浏览器渲染出来量。**（2026-09-20 补）
    用户报了三处对齐问题（添加框太贴列表、输入框左边没跟下面文字对齐、系统全局那行的开关没跟别行对齐）。
    我第一反应是照着 CSS 推（"`.skiprow` 有 2px 内缩，差 2px"）——**全错**：真渲染出来的第一处原因是
    **卡片里三块东西的顺序是** bar → 标题 → 列表，**添加框跑到了列表标题上面**，而那一眼看不出是顺序问题。
    - **`_diag/panel_preview.js` 就是干这个的**：把**功能真发的那份文档**（`feature_keepawake_probe.cpp` 的
      第三个参数可以把它写出来）交给真页面，用 Edge 无头渲染，**出图**（`--screenshot`）**并且出数**
      （`--geom`，把各元素的 `getBoundingClientRect` 写进 `document.title`，配合 `--dump-dom` 读回来）。
    - **判据：凡是"看起来没对齐/太挤/太大"的问题，先量。** 图告诉你"不对齐"，数量告诉你**差多少、差了谁**。
      改完再量一次：那次三个数分别是 `sw0a/sw1a 都是 x=815`、`ghost/btn1 都是 987 宽 52`、`input/name 都是 x=243`。
      ⚠️ **英文下按钮宽 74、中文 52**——所以"占位"用的那个幽灵按钮必须是**同一个标签造出来的真按钮**，
      写死像素宽度在另一种语言里就是错的（这条也是量出来的，`panel_preview.js` 的第 7 个参数选语言）。
    - ⚠️ **看图要当心**：我对着深色图说"这是浅色"——像素采样才是准的（`#141414`/`#1A1A1A`）。**颜色用像素说，
      尺寸用 rect 说，不要用"我看起来"说。**
    - ⚠️ **改了页面用到的 DOM API，就要把每个桩补齐**：页面这次开始**移动**一个元素（读数被搬进列表栏），
      于是三个探针桩（`apex_panel_probe.js`、`apex_edit_probe.js`、`apex_edit_sequence_probe.js`、
      `apex_real_doc_probe.js`）都要有 `insertBefore` 和"`appendChild` 会把子节点从旧父亲身上摘下来"的语义。
      **是门抓到的**（桩没有 → 页面在第二条消息上就崩），不是我想起来的。

**页面错误会回传**：`reportError()` 把 JS 异常发给宿主写进日志。没有这条通道时，
页面里的错误从外面完全看不见（表现和"没收到消息"一模一样）。

15. **⚠️⚠️ 要活过重绘的东西，绝不能被搬进"每次都会清空"的那棵子树里。**（2026-09-20 补，**是我自己造的**）
    实时读数那一版，我把读数框**移动**进了插件的列表栏（为了放到「添加」右边），看着很聪明——可
    `renderFeature` 第一句就是 `b.innerHTML = ""`，于是**下一次重绘把那个框销毁了**，而宿主每秒调一次的
    `window.__apexLive` 还在 `$("live")` 上取元素 → 每秒抛一次 `missing element #live`。
    **实测面板日志里 2122 条**，而用户看到的是「**那个提示不见了**」（他的原话）。
    - **判据：一个元素的存在期由谁决定，它就得待在谁的地盘里。** 读数框当初是 `#body` 的**兄弟**，
      正是因为它要活过重绘（§3.5.2）；把它挪进去，就是把这个前提亲手拆掉。
    - ⚠️ **异常发生在渲染的最后一行时，页面看起来是"正常的"**——所以这类 bug 只能靠**日志里的 pageError**
      或"某块区域没画出来"发现。**「参数面板是黑的」**就是同一个形状：暗色主题下 `--bg` 是 `#141414`，
      **没画出来的那块 = 一块黑**。（用户报的那一处最后查出是**撞色按钮**，不是这个；但两者长得一样，
      所以判据要能同时区分。）
    - **工具**：`_diag/panel_preview.js` 现在能**点一次按钮**（`--press=添加 --after=<文档>`）并把页面自己
      报的错收进 `document.title`——**流程**里的异常，DOM 桩（无绘制、无命中测试）永远看不到。

16. **⚠️⚠️ 异步"做完了没有"不许猜，要让做完的那一方说出来。**（2026-09-20 补）
    「点捕获 → 鼠标点一下 → 结果马上出现在参数页」这件事，页面**当场不知道**（结果在功能自己的线程里产生），
    所以它只能问。第一版的做法是：**文档变了就算做完了**。这个猜测两头都错——
    - **结束得太早**：宿主对**每个 `listOp` 都回一个快照**，页面收到快照会重读一遍，而重读到的文档和"开始等"
      时的那份**本来就不一样**（功能已经进入等待，文档里多了一个字段），于是**等待在刚进入捕获状态的瞬间就
      被判成完成了**。用户报的正是这个：「**捕获事件进行时，鼠标点击后结果要马上给到参数页，目前没有，要等到
      点击新建的规则条才会出现**」——他点一下规则条，页面才重新读一次，结果才出现。
    - **永远不结束**：捕获到的内容恰好和原来一样时，文档**根本不变**，页面会一直问下去（一个看不见的死循环）。
    修法是让**功能自己说**（`group` 的 `waiting`，ABI 10→11）：页面只在它说"还在等"的时候继续问，它不说了就停。
    **判据：一个"别人什么时候做完"的问题，答案必须在做完的那一方手里，不能从"数据变没变"反推。**
    - ⚠️ 功能那侧**清掉这个标记必须排在"结果已经写进文档"之后**（就是两行的先后），否则又开一个同样的口子：
      页面会在结果还没写进去的那份文档上停下。

17. **⚠️⚠️ 重读"当前这一页"不许把它清空。**（2026-09-20 补，**也是我自己造的**）
    `loadFeature(slot, force)` 原来在 `force` 时把 `S.controls` 清成 `null`，而**每个 `listOp` 之后宿主都会
    回一个快照**，页面收到快照就 `loadFeature(S.view, true)` 重读——于是**任何一次 `listOp` 都会让插件页空一帧**
    （`#body` 空着，暗色主题下就是 `#141414` 一块黑）。用户报的是「**新建规则后，插件面板还是会变黑，直到鼠标
    点击完成捕获后它才显示**」，而真正的触发条件是"任何一次 listOp"，他只是在新建规则时最容易看到。
    - **判据：判断"要不要丢掉手上的数据"要问"我是不是换了页"，不是问"这次重读是不是被要求的"。**
      现在是 `if (leaving) S.controls = null;`，而 `force` 这个参数因此**没有别的含义**，已经删掉
      （`askControls` 才是真正去要数据的那一步）。
    - ⚠️ **同一个症状我打了两次补丁，第二次才到根**：第一次是在捕获监视器的守卫上开例外
      （"文档没变、但页面是空的"就照样画）。它治好了黑屏，**却把等待弄死了**——正是第 16 条那个
      "结果要等点一下才出现"。**判据：一个症状如果要用"例外"来修，先问这个例外在替哪条本该成立的规则擦屁股。**

18. **⚠️⚠️ 列表里的"名字那一列"要按内容量出来，三个要求一起满足。**（2026-09-23 补，用户报的）
    用户的原话：「**设置里，设备名称宽度自适应缩到最短，给推子让空间，但每个小面板各控制要保持对齐.**」
    这三句各自否掉了一个显而易见的答案：
    - 名字那一列原来是**弹性**的（`.skiprow .nm { flex: 1 }`），于是 1100 px 的窗口里它吃掉每行约 500 px，
      而推子固定在 150 px——**"给推子让空间"说的就是这件事**；
    - 每行各写 `width: max-content` 最短，但**不对齐**：三个显示器名三个宽度，推子会从三个不同的 x 开始；
    - 每张卡统一写一个固定宽度会对齐，但短名字的卡（「系统声音」、"firefox"）就浪费掉一截。
    **做法**：`fitNameColumn`（panel.js）**量**——在一张卡里造一个同字体同文本的隐藏 `span`，取最宽的那个名字，
    把那个宽度写给**这张卡的每一个**名字格；两个同字体同文本的 span 宽度相同，所以这是算术而不是审美。
    - ⚠️ **量必须在页面进入文档之后**（`renderFeature` 的最后一行调 `fitNameColumns`）：**没进文档的元素
      `offsetWidth` 全是 0**，在 `groupCard` 里边建边量会静默地什么都不做，名字列就还是样式表里那个值。
    - ⚠️ **而且要能在"没有布局"的环境里活着**（DOM 桩）：`offsetWidth`/`getComputedStyle` 逐层守卫，
      **量不出来就保持样式表里的宽度**——那样页面和这个函数存在之前长得一样，是好的失败方向
      （和 `barItems` 那条同一个理由：桩里抛异常会让整页不渲染）。
    - ⚠️ **推子那侧要跟着改**：行的控件组与 `range` 都变成弹性的（`flex: 1 1 auto`），不能拉伸的（快捷键那行）
      用 `justify-content: flex-end` 贴右——否则它会从右边漂到名字后面。
    - **工具**：这一条是**看图定的**（`_diag/panel_preview.js` 渲染 MediaControl 的真文档），不是照着 CSS 推的。

19. **⚠️⚠️ 标题右边的计数只对"用户能加的列表"有意义。**（2026-09-23 补，用户报的）
    用户的报告：「**媒体插件设置三个面板，"亮度""熄屏快捷键""音量"对应的小标题右侧有个数字，是用来计数的？那个不需要，
    可以去掉.**」——那个数字是**通用的**（`groupCard` 里的 `rownote`，数的是**用户自己加的行**，`locked` 的不算），
    对 KeepAwake 的程序名单、AutoIME 的规则表都是有用的答案；而 MediaControl 那三组**每一行都是机器给的**
    （`noAdd: true` + 每行 `locked`），于是它永远显示 `0`。
    **修法是一条通用规则，不是给这个功能开例外**：`if (!p.noAdd)` 才画那个数字——
    "你能往里加东西吗"决定了"这里有几个"是不是一个问题。
    - ⚠️ **这条也有门**：`apex_panel_probe.js` 两边都断言（能加的列表**有**数字、机器给行的列表**没有**）。
    - ⚠️ **写这个断言本身踩了一个坑**：`renderGroup()` 是**画进同一个容器**的（`bodyRows` 就是它，就地清空），
      所以新加的那一段跑完**必须把页面画回去**——第一次没画回去，后面三条检查（添加框、Add 按钮、bar 里的
      按钮数）当场全红，而它们和这条改动毫无关系。**判据：一个检查如果借用了共享的现场，它就欠现场一次恢复。**

20. **⚠️⚠️ 为某一个功能写的"字段要撑满一行"，在列表行里就是"控件宽得离谱"。**（2026-09-23 补，用户报的）
    用户的原话：「**置里，熄屏快捷键 小面板，每个设备后面有个"快捷键"的文字去掉。快捷键居右对齐，不用那么宽，
    够装快捷键字就好，中间可以留空.**」——「那么宽」是**实测**的 ~480 px。
    - **原因不是这一行写错了，是别处的规则漏进来的**：`.grp input[type="text"] { flex: 1 }` 是**为另一个功能**
      写的（它的字段是长模式串，"一行撑满"才对），而 `.hotkey` 自己就带 `flex: 1`。于是列表行里的控件
      **谁弹性谁就吃掉整行**——宽度是行给的，不是控件要的。
    - **修法**：这一行里的控件一律 `flex: 0 0 auto`，**哪一个是弹性的由这一行自己决定**（列表行里是推子）；
      而"够装字就好"用 `width: auto`（内容宽度，`max-width` 兜住病态长的内容）表达，
      **不要写死一个 em**：写死 9em 时渲染图里是 `Ctrl+Alt+Shift+…`——**省略号吃掉的正好是"哪一个键"**。
    - ⚠️ **顺带删掉了这一行的字段标签**（功能侧把 `labelZh/labelEn` 发空）：这一行的行首就是设备名，
      一个控件，和上面那组的名字框、推子是同一条规矩；门现在**在文档上**断言这个空标签
      （源码扫不到：空串是另一次调用发出的）。
    - **工具**：这条同样是**看图定的**——`_diag/panel_preview.js` 拿**带一条已录快捷键的设置文件**渲染
      （把 ini 放进 dump 用的暂存目录即可），一次 15 秒，比部署-反馈的循环快两个数量级。

21. **⚠️⚠️ 窗口尺寸要有个下限，而它不是一个 CSS 能解决的问题。**（2026-09-23 补，用户报的）

    用户的原话：**「设置面板宽度要有一个最小值限定，往小了拉，插件有些控件会超出面板」**。

    - **成因**：面板页面**不是文档，是一个布局**。它不会像网页那样在窄了之后重排——行里的东西按它们的最小宽度
      排不下时，右端（读数、开关、移除按钮）就直接被切掉或者被挤成乱码。
    - **修法在窗口这一侧**（`ui_webview.cpp` 的 `WM_GETMINMAXINFO`），**不是在样式表里**加一条 `min-width`：
      给 `body` 一个最小宽度，只会让页面在同一个太小的窗口里横向滚动，那是"症状换了个样子"。
    - ⚠️ **两个数是 CSS 像素，而 `WM_GETMINMAXINFO` 说的是设备像素。** 这个进程声明了 per-monitor DPI 感知
      （`settings.manifest`）：150% 的屏上，800 设备像素的底线只有 533 CSS 像素，比它要防的那个东西还窄。
      所以有一个 `PanelScalePercent`（`GetDpiForWindow`，**按名字取**——老系统上没有这个函数，
      那时用 96 而不是猜），两个常量按它缩放。
    - ⚠️ **数字是量出来的，不是推出来的**：`_diag/panel_preview.js` 把功能**真发的那份文档**在真浏览器里按指定
      宽度渲染（1100 / 800 / 700 各一张）。最宽的那一页是 MediaControl 的（设备名 + 自定义名字框 + 推子 +
      读数 + 熄屏开关挤在一行）：**800 时每一行都还在卡片里**（名字开始被裁，那正是省略号和"五格名字"要处理的
      事），**700 时名字已经被挤成乱码**。所以底线是 **800 × 520**。
    - ⚠️ **它管的是"拖不动"，不是"进不去"**：`ptMinTrackSize` 只约束用户拖边框；代码自己 `MoveWindow` 到更小
      仍然做得到（现在没有人在做，但将来有人做的话，别指望这个常量拦着它）。

22. **⚠️⚠️ 一组的开关画在"这个组自己那一行"，而哪一行要看这个组已经有什么。**（2026-09-23 补，用户定的）

    用户一次说了三句（快速面板那一轮，ABI 16 → 17 的 `group.quick`）：

    > 「保持唤醒插件…放在「添加」按钮右侧，居右」
    > 「媒体控制插件…位置移到亮度和音量各自小标题的右侧，居右」
    > 「滑动滚轮插件…位置就放在现在的「最高速度」那边」

    **三句是一条规则**：这个开关画在**这个组自己的控件所在那一行的最右端**（`.quicksw` 的 `margin-left: auto`，
    这就是"居右"）。而"哪一行"由这个组**已经有的东西**决定：

    * 有「添加」框的组（名单是用户自己加的）→ **加框那一行**（`bar`），它在卡片**外面**，是用户加东西的地方；
    * 行是**机器给的**组（`noAdd`，没有加框）→ **小标题那一行**（`listhead`，在卡片里）；
    * **两样都没有**的组（`stack`、`master`）→ 它**根本没有自己的小标题**（`listhead` 只在 `layout:"rows"`
      时才建），所以只剩 `bar` 可以用。

    ⚠️ **第二、三种必须分开，而判据是"有没有加框"，不是"有没有 bar"**：`noAdd` 的组照样可以有 `actions`
    （MediaControl 的音量组有一个「刷新应用列表」按钮），那种组是有 `bar` 的——用"有没有 bar"当判据就会把
    音量组的开关放到卡片上方去，而用户明确要它在**小标题**上。

    - ⚠️⚠️ **顺带修掉的一个真 bug（这一轮才发现的）**：`barItems` 是"这个 rows 组的 bar 要不要画"的判据，
      而 `actions` 那段循环**从来没有给它加过一**——于是"行是机器给的 + 声明了 action"的组（正是 MediaControl
      的音量组）**整条 bar 连按钮一起被丢掉**：`刷新应用列表` 从写出来那天起就没在屏幕上出现过。没有任何东西
      报错，因为**唯一带 actions 的夹具是 master 布局的组**，而那种组的 bar 是无条件画的。
      **判据：一个"造出来又扔掉"的控件，只有那条路有夹具才看得见**——现在探针也喂一个 rows + actions 的组。
    - **门**：`apex_panel_probe.js` 四种组各断言一次（机器给的组画在小标题上、要加的组画在加框那一行且是那一行的
      最后一个、有 action 的组仍然画 bar 而开关仍在小标题上、没有小标题的组画在 bar 上），外加"没声明 `quick`
      的组一个这样的开关都不画"。**故意把落点改错跑了一次**（一律画进 bar）：四条当场红。

23. **⚠️⚠️ 通用页上的"顺序"列表：页面画、宿主排、拖一下发整串。**（2026-09-23 补，用户定的）

    用户的话：**「设置通用里，把快速面板功能单独给一个小面板，在两个总开关下面实时给出当前有映射在快速面板的功能，
    并能实现上下排序。总开关不参与排序，固定最上面」**。于是通用页上「快速面板」那一行（两个总开关）下面多了一张
    卡片：**只列当前真的有映射的功能**，可以拖动排序。

    - ⚠️ **页面有三件事故意不做**：
      * **不判断"哪些功能映射了"**——它拿不到那个事实，只有功能自己知道（`quickItems` 返回 0 就是没映射）；
      * **不排序**——顺序由宿主解析好后随快照发下来（`quickOrder`，见 `hostconfig.h`）。页面自己排一遍就是"顺序"
        的第二份实现，而这份列表的**全部意义**就是让用户看到浮层将会怎么做；
      * **不自己重画**——拖完只发一条 `setHost`，宿主答一次快照，列表照宿主的真实存储重画（和这一页别的控件同一条
        规矩：页面不是守门人）。
    - ⚠️ **拖动用的就是列表那一个实现**（`makeDraggable`）：同样的 `cursor: grab`、`dragging`、`dropover` 三句

    - ⚠️ **两个总开关不在列表里**，因为"总开关"不是一个功能、也没有顺序（用户明说了"固定最上面"）。探针专门断言
      这一点：列表行里一个开关都没有。
    - ⚠️ **而"整串替换"有一个反直觉的一半**：页面发回去的是**它正在显示的那几个**，可宿主**不许因此丢掉没显示的
      那些**——某个功能此刻没映射就没有行，但它原来的位置要留着（下次映射回来时回到原处）。规则是"先按发来的顺序，
      再把没提到的按原顺序接在后面"，空值等于什么都没说而不是清空（见 `hostconfig.h`）。
    - **门**：`apex_panel_probe.js`（顺序照宿主给、总开关不在列表里、拖动发一条 `quickorder`、没映射时说的是一句话
      而不是空框、**旧宿主不发这个键也不崩**）＋ `check_apex_hostconfig.sh`（合并规则与文件往返，
      **故意把合并那半去掉跑过一次，四条当场红**）。
