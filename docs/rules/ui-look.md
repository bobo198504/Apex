### 3.7 语言与主题：三处都要跟，缺一不可

| 位置 | 机制 | 坑 |
|---|---|---|
| 面板页面 | CSS `prefers-color-scheme` | 无（浏览器自己处理） |
| 窗口标题栏 | `DwmSetWindowAttribute` | **必须主动调**，否则深色页面顶着浅色标题栏 |
| 托盘图标 | `LoadImageW` + `NIM_MODIFY` | 旧图标要在 shell 收下新的之后再 `DestroyIcon` |
| 窗口图标 | `WM_SETICON` | **类的图标是缓存的**，改主题后必须重设 |

**「哪个主题在用」只有一个答案，而且是纯函数**：`hostconfig.h` 的 `ThemeResolvesLight(theme, systemIsLight)`。
**钉住的 light/dark 盖过系统**，`auto` 才看系统。托盘、窗口图标、标题栏、页面四处都问它。

⚠️ **但在页面开口之前，只有 `apex.ini` 知道答案**（2026-09-18 修，**门抓到的，不是眼睛**）：
面板进程要**先建窗口、再建浏览器、页面才跑起来**，而在那之前它得决定标题栏、窗口图标、以及浏览器
**首帧要画什么颜色**。这四处原来一律退回**系统主题**——`auto` 下是对的，**钉住时全错**。
最难看的一次：**系统深色 + 钉住浅色 → 面板先画一整屏近黑**（`#10130c`），然后再变成浅色。
用户报的是"先白一下"，这是藏在它后面的**更深的一次闪**。
- **修法**：`ui_webview.cpp` 的 `ResolveAppearanceFromConfig()` —— 用**同一个** `ParseHostConfig`
  读 exe 旁边的 `apex.ini`，再用**同一个** `ThemeResolvesLight` 解析。`hostconfig.h` 是纯头文件，
  面板进程能直接读，不需要问宿主、也不需要宿主在跑。
- **判据**：**凡是"页面还没开口"时要用外观的地方，都问这个函数**，不要问系统。
- `test\check_apex_flash.sh` 把「面板告诉浏览器画什么颜色」和「`panel.html` 自己声明的 `--bg`」
  两处对起来验，明暗各一遍。**它验不了"闪不闪"**（那是几帧的事，得用眼睛）——它验的是
  **机械可查的那一半**：调用发生了、运行时收下了、颜色就是页面自己那个。

⚠️ **这条规则曾经被绕过，结果是图标不跟随**（2026-09-18 修）：

1. **图标资源根本没注册上。** `apex.rc` 写的是 `IDI_APEX_LIGHT ICON ...` 这样的**名字**，
   而 `#define` 在 `main.cpp` 里——**资源编译器看不到 C++ 的宏**，于是图稿以**字符串名**登记，
   代码按 `MAKEINTRESOURCE(2)` 去要 → **NULL**。托盘被交给"空图标"，shell 就继续显示原来那张。
   `.rc` 里没定义的名字**不是错误**，windres 一声不吭。
   **修法**：两个编号收进 **`apex\icons.h`**，`.rc` 与 `.cpp` 都 include 它（资源编译器有自己的预处理器）。
   **`test\check_apex_icons.sh` 从产物验**：把两个 id 按产品的方式 LoadImage 出来、量像素。
2. **日志报的是"选了哪个"，不是"加载到没有"。** 那行旧日志写 `icon=dark-mark`，看着像证据，其实只说了意图。
   现在写 `icon=.. (.. theme, ..) load=ok`，**id 与加载结果出自同一次调用**，不可能互相打架。
3. **钉住主题对托盘无效。** 面板改 theme 时 `settings_host.cpp` 标了"影响托盘"并触发刷新，
   但托盘那次算的是 `SystemIsLightTheme()`——**设置说了要管，代码没管**。现在走 `ThemeResolvesLight`。
4. **面板这侧同理**：页面才是「解析结果」的权威（`data-theme` 在页面里），
   它把 `dark` **和 `pinned`** 一起发给宿主。`pinned` 不能省：
   钉住时页面**不会**在系统主题变化时重报，宿主必须知道"别重读系统"，否则下一次系统切换会把钉住的主题悄悄顶掉。
5. **⚠️ 亮暗映射被写反过一次**（用户报的"图标亮暗反了"）。**先看图再说怎么映射。**

**图标是「底板 + 记号」，底板与它所在的那条栏同色，反的是中间的记号。**

| 文件 | 是什么 | 用在哪 |
|---|---|---|
| `apex-light.ico` | **近白底板** `#FFFDEF` + 黑记号（2026-09-19 用户重画："Light图标应该是要白的，当时没设计好"） | **浅色外观** |
| `apex-dark.ico` | **近黑板底** `#10130C` + 米色记号 | **深色外观** |

所以映射是**顺的**：浅色外观 → `IDI_APEX_LIGHT`，深色外观 → `IDI_APEX_DARK`。**文件名本来就说的是这个。**

**我是怎么弄反的**：脑子里装的是「浅底要深图标才看得见」——那对**光秃秃的记号**成立，
而这两个图标**带底板**；底板跟着背景走才对，否则会在任务栏上贴一个不匹配的亮块或黑方块。
更糟的是**量了像素反而更自信**：均值量到的正是**底板**，于是"米色那张更亮"被我读成"它该用在深色桌面上"。
**教训：映射关系要看图确认，不要从中位数/均值反推；而且这种映射错误会让"宿主请求了哪个 id"那类断言
一路保持自洽地通过。**

**这扇门因此补了一条连接**：`check_apex_icons.sh` 现在**读回宿主自己窗口手里的图标像素**，
把「外观 → 日志里那个名字 → 名字背后那张图」三样串起来。
（托盘读不回来——它归 shell 所有；但宿主窗口通过同一个 id、同一个函数设图标，是同一个决定。）
**实测**：浅色底板 luma ≈252（重画前是米色 228）、深色底板 luma 25，差得足够远，交换一定看得出来。

**托盘文字必须用 W 系列 API**（`Shell_NotifyIconW`/`AppendMenuW`）。
实测本机走 ANSI 路径时"端"只有 2 字节（正确 UTF-8 是 3 字节）——就是乱码来源。
（`TrackPopupMenu` **没有** A/W 变体：Win32 菜单内部就是 UTF-16 存储。）

### 3.7.0 ★★ 托盘右键菜单**没有了**：四个命令进了快速面板的页脚

用户原话（2026-10-12）：**「把原来的右键菜单三个功能和退出，直接做到快速面板下方4个按钮，类似于 win11 开始菜单
下面的右下的按钮。然后不管左键还是右键单击都是这个菜单。这样就算快速面板没有打开任何插件开关，它也有东西显示」**。

**所以这不是"给托盘加个入口"，是托盘不再有菜单了。** 左右键都开快速面板，四个命令是它的页脚。

| | 之前 | 现在 |
|---|---|---|
| 左键单击 | 开快速面板（**要等一个双击超时**） | 开快速面板（**立即**） |
| 左键双击 | 开设置 | 同上（不再有第二含义） |
| 右键 | 弹 shell 菜单 | 开快速面板 |
| 四个命令 | 菜单项 | **面板页脚的四个图标** |

⚠️ **双击等待因此一起消失了，这是白捡的。** 以前左键必须压住一个 `GetDoubleClickTime()`，因为"单击开面板、双击开设置"
在超时过去之前分不出来。现在设置是**面板里的一个图标**，没有要猜的东西——面板在**按下**时就出来，而不是最多半秒后。

⚠️⚠️ **而且它顺手删掉了一个未文档化 API：`SetPreferredAppMode`（uxtheme 序号 135）。** 那个调用存在的**唯一**理由是
`TrackPopupMenu` 由 shell 画，钉住的外观够不着它——菜单一旦不存在，它就没有作用对象了。一个没有效果、未文档化、
还会随 Windows 版本挪序号位的调用，正是这个项目已经删过一次的那类东西（亚克力）。

### 3.7.0.1 页脚：**一整块面板**，四个图标裸放在里面靠右

⚠️⚠️⚠️ **这一处返工了三次，三次都是用户看着屏幕说的，而且每次说的是更准确的那一层：**

1. **「面板颜色要统一，按原来面板元素加一个就好，不要单独做」**——当时是"一条横贯面板的分隔线 + 每格一个词"，
   那是这个面板的**第二种视觉语言**（它本来只有一种：板块）；
2. **「颜色不对，就把它当成一个"插件开关"面板就可以了，原来添加都可以直接是一样的，不要单独写」**——
   于是每个按钮穿上了板块的材质；
3. **「还是不对，是要整体的面板，不是只有按钮的底色」**——**这一句才点出真正的错**。

⚠️⚠️ **差别在于"这层表面属于谁"，而且它是可以用数数判定的：** 四个各自带材质的小方块之间**留着三条缝**，
缝里透出的是面板本身——**眼睛数到的是四个东西**；而一整块板里放四个图标，**眼睛数到的是一个**。
"页脚"读起来像页脚，靠的就是这个。

**落在地上的形状**（`apex/quickpanel.h`）：

| | 是什么 |
|---|---|
| `Layout::footerPane` | **那块板**：与上面每一个板块**同宽**（内容全宽）、同一圈 `sectionPad` 内边距，高度 = `2×sectionPad + footerH` —— 和"单行板块"的算法完全一致 |
| `Layout::footer[4]` | 板**里面的四个图标位**（不是四个按钮），靠右、等距，最右一个距板右缘一个 `sectionPad` |
| `Layout::footerStrip` | 四个图标位 + 它们之间的缝，**保留只为命中判定**：缝里点到要什么都不做，而不是打开隔壁那个 |

⚠️ **图标 hover 时变的是"墨色"，不是背景**：静息 `--sub`，指针在上面 `--fg`——这一对颜色面板本来就在用
（"一个标签"和"你正指着的东西"）。既然板已经是板，再叠一层高亮底色就又回到"按钮"那个读法了。

⚠️ **四个图标是面板已有的 24 单位方框线稿**（和推子右边那个静音/熄屏按钮同一套），所以 125%、200% 缩放不用第二组数字。

### 3.7.0.2 四个图标：**两个第一次画反了，靠放大看成图才发现**

| 按钮 | 图标 | 怎么画的 |
|---|---|---|
| 设置 | 齿轮 | 一个环 + 中心空心圆 + 八根齿 |
| 打开文件夹 | 文件夹 | 轮廓：**左上角的"耳朵"** + 下方本体 |
| 查看日志 | 一页纸 | 折角的页面 + 三条内缩横线 |
| 退出 | **一个 X** | 两笔圆头对角线，半对角 5.9 单位（见下面那条：它和电源按钮比过） |

1. **文件夹的耳朵画在右边** → 看起来是**对话气泡**。真实文件夹的舌头在**左上**；
2. **电源按钮的缺口开在右边** → 看起来是**刷新/重来箭头**。⚠️ 原因是 GDI+ 的圆弧角度**从 3 点钟方向顺时针**量，
   12 点方向是 **-90**；要留一个**正上方**的缺口，弧必须从 `-90 - 缺口/2` 开始画 `360 - 缺口`。那一版写的 `-110, 220`
   把缺口放到了右边。

**判据：图标这类东西必须看图确认，不能靠读角度参数确认。** 这与本节上面"图标亮暗写反"的教训是同一个错误的两种形态。

#### ★★ 而"退出"最后用的是 X，**是两个候选并排渲染出来比过之后才定的**

用户的话：**「退出做成电源按钮，或者一个X也行，看哪个好看」**——这是一个关于**画面**的问题，所以按这个项目的规矩**渲出来看**，
不靠描述（`_diag/` 里那个一次性对比探针，任务完成后已删除）。

**两个候选各渲染一张真面板**（同一个 `PaintPanel`），并排放在一起，真实尺寸 + 放大各一份。图说服了人：

- **X 的笔画粗细和跨度与旁边三个一致**。电源按钮那个环在 19px 下**光学上偏轻**，在一排四个里像"另一个人画的"；
- **X 是这排里最简单的形状**。环 + 缺口 + 一竖，在小尺寸下要分辨三个特征；两笔交叉只要分辨一个。

⚠️⚠️ **对比的第一版是假的，我把它扔了**：我试着在已经画好的面板上**覆盖**一个 X，结果擦除笔画在页脚玻璃上留下了一块浅色补丁，
位置也偏了——**那张图对 X 不公平**，它显示的是叠加的效果，不是实现后的样子。
**判据：做二选一的对比时，两个候选都必须走真正的绘制路径；"盖上去"必然带进它自己的瑕疵。**

⚠️ **落选的分支和那个临时开关都删掉了，没注释掉**：对比用的东西不是功能，输掉那方的几何不该留在出厂代码里。**判据：图标这类东西必须看图确认，不能靠读角度参数确认。** 这与本节上面"图标亮暗写反"的教训是同一个错误的两种形态。

### 3.7.0.3 ★ 页脚不是插件控件，所以它不在 `Model` 里

⚠️ **那是设计要点。** `Model::items` 里的每一样都来自某个插件的 `quickItems`、归那个插件所有、用户取消映射就消失。
这四个图标是**宿主的**，插件做什么它们都在。所以：

* `FooterAction`（`quickpanel.h`）是四个动作的枚举，**与 `Model` 平行**；
* `HitKind::kFooter` 是**自己的一个 kind**，不是"kNone 带个下标"——页脚不是插件控件，点它的回答是**跑一条宿主命令并把面板收起来**，
  这与其它任何 kind 都不同。报成 `kNone` 会让点「设置」**悄无声息地什么都不做**；
* ⚠️ **四个命令只有一份实现**：`host::QuickPanelCommand` / `QuickPanelCommandLabel`（`main.cpp`，声明在 `host.h`）。
  **面板是"第二个够得着它们的地方"，不是"第二种做法"**——具体到"查看日志"：如果面板自己开一个 `apex.log`、而菜单开的是另一个，
  那就是同一个问题有了两个答案。⚠️ **顺序是"先收面板，再执行"**：用户是在浮在托盘图标上的面板里按的，
  设置窗口从还立着的面板后面钻出来会正好盖住他刚要的东西。

⚠️⚠️ **`MeasureModel` 不再对空模型返回 0 了，这是用户那句话的直接后果。** 以前"空模型 = 什么都不画"，理由
（"只有边框没有内容的面板比没有面板更糟"）在面板**只**由插件控件组成时成立。现在页脚**就是内容**：设置里把两半都关掉，
面板仍然有东西显示、有东西可点。用户的理由也正是这个项目反复学到的那条——**一次点了没反应的点击，看起来和程序坏了没有区别**。

⚠️ **门跟着改了断言，而且改的是断言而不是实现**：`_diag/quickpanel_probe.cpp` 里原来那条
`"an empty model measures zero (nothing to show)"` 断言的正是用户要改掉的行为。现在它断言相反的四件事——空模型仍然量得出页脚、
四个图标都可点、**页脚是一整块内容全宽的板**、**四个图标在它内部且整体靠右**、板的高度是 `2×sectionPad + footerH`。
另外加了一条**读源码**的断言：页脚那段必须调用 `DrawGlassPane`（与板块同一个函数）、且不许有自己的填充色——
"页脚有没有自己的颜色"从一个不画图的探针里问不出来。把页脚改回自绘填色跑了一次，**门当场红**。
### 3.7.1 面板的两套配色（**浅色与深色的主次是相反的**）

**深色的两个真值仍是图稿采样的 `#10130C`（近黑）与 `#191D15`（稍亮的卡片）。浅色不再是图稿的米色了**——
见下。两个主题的"主次"方向本来就不同，这是用户指定的（"大背景用更浅的，功能区用稍深点的"）：

| | `--bg`（大背景 / 侧栏） | `--panel`（卡片 / 功能区） |
|---|---|---|
| **浅色** | `#FAFAFA`（**更浅**） | `#F2F2F2`（稍深，卡片像"凹进去"） |
| **深色** | `#141414`（近黑） | `#1A1A1A`（**稍亮**，卡片因此才看得出来） |

**深色不能跟着一起翻**：深色下把卡片做得更暗就等于看不见。浅色是**底下浅、上面深**，深色是**底下暗、上面亮**。

⚠️ **2026-09-19 起，两套都是饱和度 0 的纯灰**（用户："原来有偏米黄的元素都去掉，改成饱和度为0的色系。滑动开关那些颜色保留原样"）。
**语义色不动**：`--warn`、三个状态点（开关也用它们）是信号，不是底面。

⚠️ **⚠️ 浅色为什么不能用图稿的 `#F4EAC6`**（用户："浅色UI，颜色饱和度改低些，让它看起来再白淡些，
现在太黄了"）。图稿那个米色是**记号里的底板**，一辈子只出现几百个像素；当它变成**整屏背景**时就是一片黄。
所以浅色这侧换成**同色系但去饱和**的一族（饱和度 84% → 22%），**而 `#F4EAC6` 的"米"保留在该出现的地方**
——图标本身、以及小面积的暖调。`--track`（滑块槽）和内描边比卡片再深一档，否则会在卡片里看不见。

⚠️⚠️ **「太黄」的真正原因不是选错颜色，是"有两个浅色主题"。** 上一次交换 `--bg`/`--panel` 时，
只写了 `:root[data-theme="light"]`，**`plain :root` 还留着旧的饱和米色**——而 `auto` + 浅色
**正是走 `:root`**（页面不加 `data-theme`）。于是**钉住浅色**和**自动浅色**长得不一样，只有一个被修过。
**修法**：`:root` 就是浅色、媒体查询换深色、两个 `[data-theme]` 选择器**把同样两套再写一遍**，
**没有任何一个是"变体"**。唯一能防住的判据是**量**，所以 `test\check_apex_palette.sh` 会读这个文件并断言：
两条路的声明**逐值相同**、卡片比背景深（深色反过来）、正文对比度过 4.5:1、饱和度确实比被否掉的那版低。

⚠️ **改 `--bg` 必须同步改 `ui_webview.cpp`**：那里有**三处**用同一个颜色（`PageBgColor` 一个函数给的）
——`DWMWA_BORDER_COLOR` 的 1px 边框、**浏览器首帧要画的底色**、以及**窗口自己的擦除色**。
不一致就会露出亮线，或者闪一下不属于任何主题的颜色。**`PageBgColor` 是这三处唯一的来源，别再抄颜色值。**

⚠️ **`test\check_apex_flash.sh` 会读 `panel.html` 里的 `--bg` 来验 `ui_webview.cpp`**——
**验的就是"这两处是不是同一个颜色"，不验闪不闪**（那是几帧的事，得用眼睛）。

**托盘刷新会打日志**（`tray: lang=.. icon=.. (.. theme, ..) load=.. tip=".."`），
因为托盘由 shell 显示、进程看不到它长什么样，**这行日志是唯一能区分"托盘变了"和"托盘没变"的证据**。保留它。
**`load=` 那一段尤其不能删**：它是"资源在不在"的唯一线索。


### 3.7.4 列表上的状态点（绿 / 灰 / 红）

用户要求：「插件列表，插件名称右边加个点，居右，绿色为启用，灰色为没启用，禁用为红色，禁用功能目前没有
开发的打算，只留接口」。

**它永远在，三选一**——不是"出问题才冒出来的徽章"。这是重点：点**时有时无**会让"关掉了"和"还没加载"
长得一模一样，而这两件事要求用户做的事完全不同。

- **颜色不随主题变，这是几何决定的不是偷懒**：一个点会落在**页面、卡片、以及选中行**上，而选中行
  **浅色主题下近黑、深色主题下近米白**。所以每个颜色都得同时顶住近白和近黑——可行区间很窄。
  实测（WCAG 非文本下限 3:1）：三个颜色在**两种主题的三种底面上都 ≥ 3.3:1**。
  若按主题各配一套就是六个数字要同步，而漏掉一对的表现是"某个主题的选中行上点消失了"。
- **⚠️ 选中行不许改点的颜色。** 旧的 `.offdot` 就干了这个：`item.sel` 时把点改成前景色——
  **点存在的唯一意义被抹掉了**，一行选中就再也看不出它是开是关。
- **红色（禁用）现在到达不了**，面板照样写好了：宿主**没有任何办法**禁用一个功能（连它自己都不行——
  只能关掉整个程序），所以这个状态**只留接口**。等宿主哪天有了这个能力，页面一行都不用改。
- `_diag/apex_panel_probe.js` 三种状态各验一遍、并断言**三个类互不相同**（否则两种状态会画出同一个颜色，
  点就在说谎）。

### 3.7.4.1 ★ 功能在替用户"hold 着什么"时怎么告诉他（**托盘三态，两个色**）

背景：`KeepAwake` 这类功能的效果**用户看不见**——机器不睡了，屏幕上看不出任何痕迹，用户是"后来纳闷为什么不睡"
的时候才发现的。用户的要求是「一旦激活就通知我，但不特别打扰」；试过之后他把"弹窗"和"托盘右键菜单里那一行"
都去掉了，最后定下来的是**图标本身**，而且**要能看出是哪一档**：

> 「这个插件只有三个状态：什么也不管，保持唤醒，保持唤醒+防止熄屏。所以托盘图标再加一种状态：什么也不管（原样），
> 保持唤醒（绿色），保持唤醒+防止熄屏（红色）。」

| 档 | ABI 的位 | 图标 | tooltip 多一句 |
|---|---|---|---|
| 什么也不管 | 不置位 | 原图稿（什么都不动） | 无 |
| 保持唤醒 | `APEX_FEATURE_USER_VISIBLE`(4) | 中间那根竖条 = **绿** `APEX_HOLD_INK` | 「保持唤醒」 |
| + 防止熄屏 | 再加 `APEX_FEATURE_HOLD_HARD`(8) | 中间那根竖条 = **红** `APEX_HOLD_HARD_INK` | 「保持唤醒 · 屏幕常亮」 |

- **图标是合成的（原图稿 + 换掉竖条的颜色），不是第三张 `.ico`**：不去重画同一张图。做法见 `apex\traymark.h`
  （GetDIBits 取像素与 alpha、量出底板色、按距离把竖条染成 ink、配一张真 mask 再 `CreateIconIndirect`）。
- **绿不是新颜色**：它就是面板状态点那个"开"绿（`--dot-on`）。那个点要同时顶住页面、卡片、选中行的近白与近黑，
  论证在 §3.7.4；`test\check_apex_palette.sh` 现在**断言两者是同一个数值**，而不是"看起来差不多"。
- **两个 ink 在两块底板上都过了 3:1**（实测：绿 5.02 / 3.66，红 4.70 / 3.90）——饱和度足够的颜色才做得到，
  这是它们能"一个颜色通吃明暗"的唯一理由。
- **谁决定哪一档**：宿主**只被告知程度**（位），颜色由宿主选（`FeatureHoldLevel()` 取所有功能里最强的那一档）。
  功能永远不点颜色，宿主永远不知道功能在 hold 什么。
- ⚠️ **tooltip 里那句"屏幕常亮"是宿主写的，这是一笔债**：宿主不知道任何功能的语义。今天只有 KeepAwake 会 hold，
  所以这句话是对的；哪天第二个功能也会 hold，就该让 ABI **带上那句话**，而不是让宿主猜得更准。（`main.cpp`
  的 `HoldLine` 那儿写着这条。）

⚠️ **历史，两次都是我错**：先做了角上一个绿点（用户："没看到"）——而它其实还有一个更深的毛病（`hbmMask=nullptr`
让 `CreateIconIndirect` 整个失败，GDI 又不写 alpha）。然后是中间竖条染橙、再加粗一像素，用户："太胖了，改回去，
用大红"；再后来才加上第二档绿。**形状一次都没改，改的只有颜色**——这是用户的原话。

⚠️ **坑（自己踩的）**：功能曾经把这些位**只在"请求发生变化"的分支里发布**——于是"为什么 hold"变了（换了一档）
而"是否 hold"没变时，旧的位还立着，**托盘会一直显示上一档的颜色**。
**判据**：这类"我在替用户做什么"的状态，**每一轮都要发布**，和"要不要调用系统 API"是两件事。
（宿主那侧同理：`WatchFeatures()` 的边沿必须盯**档位**，盯布尔量就会漏掉 1→2 这种变化。）

⚠️ **`liveText` 曾经因此有了第二个读者（宿主）**，ABI 从 7 升到 8；**档位位**又让它从 8 升到 9。
⚠️⚠️ **然后 9 → 10 把它整个删掉了**（2026-09-20）：用户看过它、又说"其实这个提示可以完全去掉。并不需要"——
**这是第二次**（第一次是 AutoIME 那个"最上方的状态提示"）。所以**字段、面板里的框、CSS、每秒一次的轮询、
宿主那条 IPC、连带着那个"独立的回复码"全没了**，而不是"留着不画"。
**判据：一个没人读的契约就是没人守的承诺**；而**IPC 的编号是退役不是复用**——面板和宿主是两个进程，
跨一次部署时旧面板还会跟新宿主说话，编号换了意思就会**悄悄做错事**（`kIpcLive = 6` 与 `kIpcLiveAnswer = 101`
都留在 `settings_ipc.h` 的注释里，标记为退役）。
